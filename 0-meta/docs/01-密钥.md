# 密钥怎么管

> 一句话：**密钥不是一个文件夹，是另一种存储介质。**工作区里只允许出现引用和密文。

## 查表：拿到东西了，放哪

| 拿到什么 | 放哪 | 工作区里留什么 |
| --- | --- | --- |
| SSH 私钥 | `ssh-add --apple-use-keychain`（生成时带 passphrase） | 只留 `.pub` |
| API key / token | 1Password | `op://Private/<item>/<field>` |
| 数据库连接串 | 1Password | 同上 |
| 必须跟着代码走的配置 | SOPS + age 加密 | `*.enc.yaml` 密文 |
| 浏览器导出的密码 CSV | 导入 1Password 后 `rm -P` | **什么都不留** |
| restic 仓库口令 | Bitwarden Lite + 本机 Keychain（仅此一口令，供调度）+ 一份纸质 | **什么都不留** |
| 恢复码 / 2FA 备份码 | 1Password | 什么都不留 |

## 三个可用形态

```bash
# ✓ 引用（推荐）
API_KEY=op://Private/my-app/api-key

# ✓ 密文（必须跟着 git 走时）
sops -e secrets.yaml > secrets.enc.yaml && rm -P secrets.yaml

# ✗ 明文（审计硬失败）
API_KEY=sk-abc123...
```

## .env 怎么办

**不要让 .env 常驻磁盘。**仓库里只放 `.env.tpl`：

```bash
# .env.tpl（进 git，安全）
OPENAI_API_KEY=op://Private/openai/api-key
DATABASE_URL=op://Private/mydb/url
```

运行时注入，两种方式：

```bash
op run --env-file=.env.tpl -- ./run.sh              # 推荐：进程级注入，永不落盘
op inject -i .env.tpl -o .env && ./run.sh; rm -P .env   # 次选：用完立刻销毁
```

## SSH 建议

```bash
ssh-keygen -t ed25519 -C "vps-prod"          # 一定要设 passphrase
ssh-add --apple-use-keychain ~/.ssh/vps-prod
```

`~/.ssh/config` 里配主机别名，工作区里只记录"哪个别名对应哪台机器"，不记录钥匙本身。

**长期目标**：改用 SSH CA 签发短期证书（开源方案 `step-ca`）。证书几小时后自动失效，私钥根本不长期存在，泄露也自动过期。这是 Netflix、Uber 这类公司的标准做法。

## SOPS 初始化（一次性）

```bash
brew install sops age
age-keygen -o ~/.config/sops/age/keys.txt      # 私钥不在工作区，另存一份到 1Password
export SOPS_AGE_KEY_FILE=~/.config/sops/age/keys.txt

# 项目根 .sops.yaml
cat > .sops.yaml <<'EOF'
creation_rules:
  - path_regex: \.enc\.ya?ml$
    age: age1xxxxxxxx...      # 上一步生成的公钥
EOF

sops secrets.enc.yaml     # 直接编辑，保存时自动加密
```

## 审计会拦什么

路径规则只看 **basename**，不看完整路径或目录名。`docs/id_rsa/notes.md`、`mysecrets.json` 不会因为名字里碰巧有一段敏感词而失败。

| 信号 | 例子 | 仅未跟踪 | 暂存或已跟踪 |
| --- | --- | --- | --- |
| 明确高危 | `id_rsa*`、`id_ed25519`、`*.key`、带私钥 PEM 头的 `*.pem` | 硬失败 | 硬失败 |
| 高概率敏感配置 | `.env`、`.env.local`、`.env.production`、`credentials.json`、`*.ovpn` | 告警 | 硬失败 |
| 模板或文档 | `.env.example`、`*.tpl`、`credentials.schema.json`、`README` | 路径规则放行 | 路径规则放行 |

`*.pem` 只凭文件名分不清证书和私钥；只有 armor 头行含 `BEGIN … PRIVATE KEY` 才当高危。暂存和已跟踪读 Git 索引里的 blob 头行，不读工作区副本；未跟踪只读工作区有限头行，且不跟随符号链接。不读密钥正文，不是全树内容扫描。

`.enc.*` 密文和 `_vendor/` 下的同名文件不走这条路径规则。路径放行不等于内容放行：暂存区仍由 `gitleaks` 搜实际秘密。

绝不把匹配到的密钥正文写进报告。

## 如果密钥已经泄露过

搬进 1Password **不解决问题**——旧的那份仍然有效。必须**轮换**：

1. 各主机先加新公钥
2. 逐台验证能登录
3. 再删旧公钥（顺序不能反）
4. 密码类的直接去服务商后台改
