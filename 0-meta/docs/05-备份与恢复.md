# 备份与恢复

> 一句话：**备份清单由策略推导，不手写；没演练过的备份等于没有备份。**

## 三份副本

| # | 介质 | 内容 | 频率 |
| :-: | --- | --- | --- |
| ① | 本机 Mac + FileVault | 全部 | 实时 |
| ② | git 远端（一个私有 monorepo） | `0-meta` `1-code` `2-infra` `4-know` + `3-data` 的契约与代码 | 每次提交 |
| ③ | restic 冷备（**两个目的地**） | 应备份集合（自动生成） | 每日 / 每周 |

**rsync 镜像不算副本。**它会传播删除——本地误删，下次同步远端也没了。它只能防硬件损坏，防不了误操作。

## git 远端也不能当成完整副本

副本 ② 只覆盖**已 commit 且已 push** 的内容。未提交的改动、未跟踪的文件，它一概不管：

```
代码的实际 RPO = 现在时间 − 最后一次 push 的时间
```

三天没推，硬盘坏了就丢三天。所以 `1-code` **同时进冷备**，不能靠 git 顶替。

职责分开：**git 管版本历史与协作，restic 管灾难恢复。**别让前者兼任后者。

## 应备份集合是算出来的

```
应备份 = 全部路径
       + 备份根之外的 external_paths（目前只有 worktree 根）
       − 可再生目录（有强/弱证据的依赖目录、缓存）
       − 构建产物（源码已提交且已推送时）
       − 保留名 _out / _cache / _vendor
       − 域 _vendor
```

对照上一版少了一行 `− 域 1-code`，多了构建产物和 `external_paths` 两行。

### 「全部路径」的起点是备份根，不是各个域相加

这两种读法看着一样，结果差很远。首次本地演练就栽在这里：源路径按
`backup.include` 的七个域拼出来，而 `.git`、`AGENTS.md`、`.gitignore`、
`.cursorignore` 这些根层条目**不属于任何域**，整批漏掉，83 个文件对 297 个。

漏掉 `.git` 尤其糟——整个版本历史就只剩 git 远端一份，而本文档上一节刚说完
git 远端不算副本。

所以：**源就是备份根本身**，`backup.include` 的角色是校验（逐个确认这些域真的
存在，缺一个就硬失败），不是枚举。`backup: forbidden` 的域走显式绝对路径排除，
不能指望它恰好和某个保留名重名——今天 `_vendor` 是这样，明天新加一个就不是。

## 实现在哪

```
2-infra/backup/scripts/
├── gen-restic-args.sh                 derived.lock → files-from + exclude
├── backup-cold.sh                     跑备份，每次先重跑生成器
├── check-closure.sh                   审计 backup_closure
├── check-password.sh                  审计口令：机器取值 / 人恢复 / 纸质声明
├── install-unattended-password.sh     把 restic 口令写入 Keychain
├── drill-local.sh                     本地替身仓库跑完整管道（不需要网络和口令库）
└── lib.sh                             读 lock、解析口令来源、rclone 限速
```

这些文件里没有任何路径常量、仓库地址、保留期数字。换目的地、改保留期、换口令库，
都是改 `policy.yaml` 再 `new plan --apply`。

```bash
2-infra/backup/scripts/backup-cold.sh --list    # 看清单，不碰仓库不要口令
2-infra/backup/scripts/backup-cold.sh           # dry-run
2-infra/backup/scripts/backup-cold.sh --apply   # 真跑
new check --tier deep                           # 闭环校验 + _raw 全量哈希
```

### `external_paths` 是为了补一个缺口

worktree 建在 `../worktrees/`——那是 仓库根的**兄弟目录**，不在备份根里。

这会让上面那条「git 远端不是备份，所以 `1-code` 也进冷备」的结论失效：工作一旦搬进 worktree，就又回到了只有 git 保护的状态，而且更糟——任务分支通常连 push 都没有。AI 跑一夜、还没 squash merge，硬盘挂了就全没。

所以备份路径要显式带上 worktree 根。同时 `new check` 的 `worktree_hygiene` 会扫每个 worktree 的 dirty 状态，在 restic 配置落地之前，那是唯一的防线。

**不要手写路径清单。**手写清单必然漂移——上一代就是这么做到「备份 15 个空目录、漏掉 3 万个真实文件」的。

## 改策略之前先看差异

`policy.yaml` 是单一事实源，也是单一爆炸点：改错一个字段，备份范围、同步范围、删除判定会同时变。

```bash
new plan        # 重算派生结果，打印 diff，高亮危险变更
```

派生结果落在被 git 跟踪的 `0-meta/derived.lock` 里，所以 `git diff 0-meta/derived.lock` **本身就是** plan——永久可查，能进 PR，不像终端输出看完就没。

策略改了但没跑 `new plan`，`derived.lock` 里的哈希对不上，pre-commit 直接拦下。这保证 policy 和它的派生结果永远在同一个 commit 里。

## 为什么要两个冷备目的地

单一云账号是相关性风险。如果你在做的事情本身可能导致账号被风控，那"唯一的备份"和"你正在压力测试的账号体系"就不是独立事件。

```yaml
destinations:
  - {name: cold-gdrive, repo: 'rclone:gdrive:…', schedule: daily}
  - {name: cold-b2,     repo: 'b2:…',            schedule: weekly}
```

## 口令别锁在保险箱里

**灾难时人用来开仓库的口令，必须存在于「你要防的那台机器」之外。**

| ✗ 错误 | ✓ 正确 |
| --- | --- |
| 口令只存在工作区的 `secrets/xxx.env` 里 | 口令库 + 一份纸质离线 |
| 口令只在本机 Keychain，没有离机副本 | Keychain（调度）+ Bitwarden + 纸质 |

典型的死循环：Mac 挂了 → 要恢复 → 需要口令 → 口令只在 Mac 上 → 回到原点。

这两个约束相反，所以拆成两个字段：

| 字段 | 回答 | 当前值 |
| --- | --- | --- |
| `password_source` | 机器怎么取（launchd 必须本机可取） | `keychain://restic-cold/restic-password` |
| `password_recovery` | 人怎么取（必须有离机来源） | `bw://restic-cold` 和 `paper` |

脚本把 `password_source` 翻译成 `RESTIC_PASSWORD_COMMAND`。口令不经过任何脚本的
环境变量，也不出现在 `ps` 里。本机 Keychain 只装这一个 restic 仓库口令，
不装 Bitwarden 主密码——爆炸半径是这份冷备，不是整个口令库。

装一次（在你自己的终端，需要看见和输入）：

```bash
cd <workspace-root>
export BW_SESSION="$(bw unlock --raw)"   # 已解锁可跳过
2-infra/backup/scripts/install-unattended-password.sh
unset BW_SESSION
```

之后日常 `--apply` / `--snapshots` 不再需要 `BW_SESSION`。换口令库或改机器取值
= 改 `policy.yaml` + `new plan --apply`。

纸质：手抄 restic 仓库口令，放到不与本机、vps1 同处的地方。然后复制
`0-meta/templates/offline-copy.attestation.tpl` 为
`0-meta/audit/offline-copy.attestation`，只填日期，**不要把口令写进仓库**。

> 上一代的口令明文躺在
> `70-infra/70-vps/credentials/secrets/vps-backup.env`，
> 和它要保护的那台机器在一起。这是教科书级的死循环。

## 口令库自己怎么备份

离机口令库（Bitwarden / 1Password / 纸）**不得**用本工作区同一条 restic 口令来保护。否则 Mac 挂了 → 要恢复 → 需要口令 → 口令只在这台 Mac 上。

所以：

- 本机挂了 → 从离机口令库或纸质取 restic 口令。
- 口令库挂了 → 用纸质直接开本工作区仓库。
- 两者同时挂了 → 纸质。这就是纸存在的理由。

## 季度恢复演练（30 分钟）

**这是整套备份体系里唯一不能省的一步。**未经演练的备份等价于没有备份。

演练必须回答一个问题：**在完全没有本机的前提下，能不能拿到口令并还原一个文件？**

```bash
# 在另一台机器（或另一个用户）下执行
export RESTIC_REPOSITORY=…
export RESTIC_PASSWORD=…            # 从离机口令库或纸质取，不许从本机 Keychain 读
restic snapshots
restic restore latest --target /tmp/drill --include <一个具体文件>
diff /tmp/drill/… <原文件>
```

结果写进 `0-meta/audit/restore-drill/YYYY-MM-DD.md`，审计会检查最近一次是否超过 90 天。

### 本地管道演练不算数

`drill-local.sh` 用一次性口令和本地替身仓库跑完整管道，不需要网络和口令库。
它证明的是「策略翻译成 restic 参数这一段是对的」，**回答不了口令那一半**——
而口令恰恰是死循环发生的地方。

记录里必须写明 `counts_as_quarterly_drill: false`，否则它会顶掉真正的演练，
制造出一种「最近演练过」的安全感。这比没有演练更糟。

## 热镜像怎么定位

如果需要给 VPS 上的 agent 投喂上下文，可以保留 rsync 镜像，但要：

- [ ] 去掉 `--delete-excluded`
- [ ] 去掉 `--checksum`（25 万文件全量哈希会拖慢到你不愿意跑）
- [ ] 远端只读挂载，防止双写脑裂
- [ ] include 清单由策略生成，禁止手写
- [ ] `5-record` `3-data` 和任何密钥永不进入
- [ ] **不计入三份副本**

上一代出事就是因为同步规则里手写了一行 `+ /…/credentials/***`，把整个机队的私钥推到了其中一台机器上。生成式清单从根本上排除这类手写失误。

## 检查清单

- [ ] 两个冷备目的地都有近期快照
- [ ] 口令：Keychain（调度）+ Bitwarden（人）+ 纸质（离机）；attestation 已填日期
- [ ] 最近一次**异机**恢复演练 < 90 天（本地管道演练不计）
- [ ] `new check --tier deep` 全绿（含 `backup_closure`）
- [ ] 审计的 `sync_safety` 无红项
- [ ] `derived.lock` 与 `policy.yaml` 同步（`new plan` 无 diff）
- [ ] restic 路径包含 `backup.external_paths`（worktree 根）
- [ ] 快照里有 `.git` 和根层文件，不只是七个域
- [ ] `new check` 的 `worktree_hygiene`：没有长期 dirty 的 worktree
- [ ] 若 `5-record` 已迁到加密卷：备份任务在挂载状态下运行
