# 5-record — 档案与凭证

## 放什么

人读的、不能重造的、不该给别人看的文件：合同、报销单据、税务材料、证件扫描件、体检报告、资产清单。

## 最重要的一条：这个域永不同步

`policy.yaml` 里写死 `sync: never`。这些东西不上任何服务器、不进任何镜像、不进任何 AI 工作目录。

审计的 `sync_safety` 检查会反查同步规则文件，确认里面没有 `5-record`。

## 为什么不做逐文件加密

直觉是「机密就该加密」，但对几百个 PDF 和扫描件逐个加密会让它们无法预览、无法搜索，结果一定是你绕过这套机制。**让人绕路的安全措施等于没有安全措施。**

实际用的组合是：

| 层 | 手段 |
| --- | --- |
| 本机静态加密 | FileVault |
| 备份加密 | restic 自带（仓库口令在 Bitwarden + 本机 Keychain + 纸质） |
| 不外流 | `sync: never` |
| 你真的会用它 | 目录和文件名自由，中文优先 |

逐文件加密（SOPS / age）只用在小体量文本配置上，也就是 `2-infra/*.enc.yaml`。

## 命名完全自由

这个域的路径脚本从不引用，所以不受小写英文的约束。按你自己看得懂的方式来：

```
5-record/报销/差旅/2025-02-北京/
5-record/合同/2026-某某公司-服务协议.pdf
5-record/证件/护照-2024换发.pdf
```

建议只保持一个习惯：**日期写在前面**（`2026-08-26-xxx`），这样按名称排序就等于按时间排序。

## RETENTION.md 是强制的

每个子目录要声明保留多久、依据是什么。缺失会被审计报出。

## 密码不放这里

浏览器导出的密码 CSV、账号密码表格，一律进 1Password。这里只放**账号清单**（有哪些账号、注册邮箱、用途），不放凭据本身。

## 策略

| 敏感度 | Git | 冷备 | 热同步 | 保留 |
| --- | --- | --- | --- | --- |
| 机密 | 禁止 | 是（restic 加密） | **禁止** | 按 `RETENTION.md` |
