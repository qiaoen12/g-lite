# _inbox — 暂存

## 什么时候用

三个问题都答不上来的时候：能不能重新生成、能不能给别人看、谁在管它。

**用它比乱放好，但它不是垃圾桶。**

## 30 天规则

超过 30 天未处理的条目，审计会报失败。

这条规则的意义不是催你干活，而是让「`_inbox` 是空的」成为一个**有信息量的信号**。没有过期机制的话，空 inbox 既可能是"管理得好"，也可能是"根本没在用"，两者无法区分。

## 备份策略是"备"

因为还不知道是什么，先保住再说。这也意味着长期堆积会白白占备份空间。

## 处理时问自己

| 问题 | 答案 → 去向 |
| --- | --- |
| 是别人的代码吗 | → `_vendor/` |
| 是我要继续做的项目吗 | → `1-code/`，建 remote |
| 是采集的数据吗 | → `3-data/`，写 `DATASET.md` |
| 是我要留着看的文字吗 | → `4-know/`，补 frontmatter |
| 是合同证件类吗 | → `5-record/` |
| **想不起来为什么留着** | → **删掉** |

最后一条是最常用的。
